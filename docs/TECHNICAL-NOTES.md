# 实现与统计说明

macOS 15.6 及以上的原生菜单栏输入统计工具。菜单栏固定占一个图标位：原图标位于左下角，右上角以小字显示今日估算字符数（如 `1.9k`）。悬停查看完整数值，点击打开按 App 汇总的主页。统计使用 Swift、SwiftUI、AppKit 和 Apple 系统 API，在本机处理；应用内更新依赖随 App 打包的 Sparkle 2.10.1，通过 GitHub Releases 分发。

## 使用

在项目目录运行：

```sh
./scripts/build-app.sh
open dist/TypeCount.app
```

也可以用 Xcode 打开 `Package.swift` 阅读和调试。日常使用应运行打包后的 `.app`，并保持路径固定，便于系统识别权限。首次打开不会自动申请权限；点击主页或设置中的授权按钮开启「辅助功能」，即可启用支持的 App 内按键与字数统计。辅助功能已包含键盘监听能力，无需再强制开启独立的输入监控权限；若只开启「输入监控」，则只能统计按键。应用会实际创建只读事件监听器，成功后才报告键盘监听可用。开启后若系统要求重启，请退出字迹再打开。

关闭主页后菜单栏继续运行。左键菜单栏打开主页，右键可暂停、恢复或退出。设置中可以排除不需要统计的 App。支持按今日、近 7 天、近 30 天查看，以及导出全部历史 CSV。

主页采用紧凑的 macOS 原生布局：默认 620 × 620 内容区，保留字符总数、时间筛选和按应用明细；趋势默认折叠，权限、排除应用与导出位于设置及更多菜单。外观跟随系统明暗模式。

设置支持「登录时启动字迹」，使用 macOS 的公开登录项接口，由用户主动开启；登录启动时仅常驻菜单栏。菜单栏可选择字数、按键或鼠标点击角标，也可仅图标，各模式都保持一个图标位，不展开为宽数字标题。完整数值放在悬停提示中。

主窗口左上角通过下拉箭头在「输入统计」和「键鼠活动」间切换，默认打开输入统计，两页共用今日/7 天/30 天筛选。键鼠活动包含左右键点击、24 小时键盘活动和常用物理键位。分布从此版本开始记录，不拿旧累计总数补造历史；键鼠分布保留最近 365 天，仅存无序计数和小时桶，不存按键顺序、输入文字或鼠标位置。功能设计参考 [keyStats](https://github.com/debugtheworldbot/keyStats)，使用本项目独立实现。

### 已开启辅助功能但应用没有识别

先点「打开辅助功能设置」核对「隐私与安全性 → 辅助功能」里的字迹，然后返回应用点「重新检查」。必要时使用「重新启动字迹」。两个权限按钮会直接打开各自的系统设置页面，应用重新激活时也会检查权限。

从早期临时签名版本升级时，旧授权可能绑定旧版本的签名，即使开关显示已开启仍会失效。请在辅助功能列表中移除旧的字迹，再用加号添加 `/Applications/字迹.app` 并开启。输入监控如遇同样问题也重新添加此路径。此操作只涉及字迹；无需重置其他应用或整个系统的隐私权限。

若重新添加后，系统日志仍显示旧签名的 `Failed to match existing code requirement`，先退出字迹，再用 Apple 提供的 `tccutil reset Accessibility com.jonah.TypeCount` 仅清理字迹的辅助功能授权；随后从固定安装路径打开应用，重新开启辅助功能开关。这会撤销字迹当前的辅助功能许可，需再次由用户授权；不会删除统计数据或重置其他 App。无需直接操作 TCC 数据库。

开发时可通过 `.signing-identity` 配置固定证书，使后续构建保持一致身份。该文件仅保存本机证书指纹，不含私钥，并已被 Git 忽略。签名身份首次切换后仍须重新授权一次。

预览界面可运行 `open -n dist/TypeCount.app --args --demo`。此模式明确显示演示标识，使用内存示例数据，不监听键盘、不改动真实统计。

## 统计口径与准确性

- **估算输入字符**：对支持辅助功能文本读取的前台编辑控件做变化差分。中文、英文字母、标点、emoji 各以一个 Swift `Character`（字素）计数，忽略空白与换行；英文按字母而非单词计算。
- 累计记录新增输入量，删除不会扣减；选择替换计入替换后的新字符。切换 App 或输入框只建立基线，不计入原有文档内容。
- **按键次数**独立统计，不会冒充输入字符数。包含文本键、删除、回车、Tab 和数字键盘，包含长按重复；Cmd / Ctrl 快捷键、导航键、功能键和单独的修饰键不计。
- Cmd / Ctrl 快捷键后的文本变化会暂时跳过，以减少粘贴、撤销、重做等影响。鼠标菜单粘贴、自动更正、脚本改写或延迟文本更新仍可能产生误差。
- 新版在编辑器提供预编辑标记时，保留提交前基线，等输入法确认后再统计新增字符。部分 App 不提供这些标记，自动更正或脚本改写也可能被合并，因此仍以**估算**标注，不能把全局 `keyDown` 当作汉字数。
- 部分浏览器、自绘编辑器、终端、远程桌面可能不暴露可读取的编辑文本。此时只记录按键，列表明确显示「仅按键」，不会用「≈0」冒充真实字符数。首次聚焦后极快的输入、切换焦点和大文档也可能漏记。
- 本机微信 4.1.11 的辅助功能树未暴露输入区。通用系统接口无法可靠取得其上屏文字，因此当前只能统计微信按键；不能承诺已经实现微信字符统计。扩展读取兼容路径始终只检查聚焦编辑框及有界的可编辑子节点，不读取聊天消息或剪贴板。

## 常驻资源策略

文本读取由键盘事件、焦点变化和编辑控件通知驱动，取消原先每 350ms 的空闲文本轮询。没有输入时不反复扫描文档；权限维护每 30 秒一次，返回应用时立即刷新。

按日、按 App 增量累计，今日计数使用索引；主页仅在实际可见时每 500ms 合并刷新。隐藏、最小化和关闭后停止列表重建，关闭主页还会释放 SwiftUI 窗口。图标缓存限定数量与成本。原文差分使用字符串索引，避免为整个文档构造两份字符数组。

统计每 5 秒在后台批量原子保存，连续输入不会一直推迟保存；退出时同步写入最新数据。鼠标仅监听点击，不引入高频移动监听。

可用 `python3 scripts/measure-runtime.py --seconds 15` 采样本机 CPU 与 RSS。短时数值依赖前台 App 和输入活动，不代表所有设备及使用情形。

## 隐私与存储

仅在本机存储日期、App 名称、Bundle ID、字符数、按键数和设置，文件位置：

```text
~/Library/Application Support/TypeCount/stats.json
~/Library/Application Support/TypeCount/activity.json
```

不保存输入原文、剪贴板、截图或窗口标题，不上传输入与统计数据。字数差分需要暂时在内存保留当前编辑控件文本；焦点切换、暂停、排除应用、安全输入和停止监听时清除。系统安全输入和通过辅助功能可识别的密码框会跳过；目标 App 自绘、未标记的密码框无法统一识别，可手动排除该 App。大型文本为避免过高开销会跳过。

统计无需联网。只有用户手动检查更新、主动开启自动检查，以及确认下载更新时，更新器才通过 HTTPS 访问 GitHub 与其发布资产服务；不包含遥测，Sparkle 系统信息上报默认关闭。

## 应用内更新

更新器使用 **Sparkle 2.10.1**，由 SwiftPM 固定版本解析，随 `.app` 打包为第三方运行时框架。默认关闭自动检查与系统信息上报，不自动下载；用户可主动开启自动检查。手动入口为「检查更新…」。

固定 feed 为：

```text
https://github.com/JonahLee1999/TypeCount/releases/latest/download/appcast.xml
```

feed 随最新正式 Release 分发，内部的更新 ZIP 则指向具体 `v<版本>` tag 下的固定下载地址。更新归档和 feed 均使用 Ed25519 签名，`SURequireSignedFeed` 与 `SUVerifyUpdateBeforeExtraction` 均开启，公开验证密钥写入 `Info.plist` 的 `SUPublicEDKey`；私钥留在发布者本机钥匙串，账户名为 `com.jonah.TypeCount.sparkle`，不导出、不提交仓库。

用户确认安装后，由更新器替换应用，并让字迹正常退出、重新启动。正常退出会保存最新统计，应用包外部的统计文件和设置会保留。没有更新器的旧版本需要手动安装一次含更新器的版本，之后可使用应用内更新。

Ed25519 验证与 Apple 代码签名、公证各自承担不同的校验。当前本地开发签名及未公证限制仍然存在，更新不能保证跳过 Gatekeeper 或辅助功能重新授权。完整打包、密钥与发布检查见 [更新与发布](UPDATES.md)。

## 开发与分发

```sh
swift test
./scripts/build-app.sh
UNIVERSAL=1 ./scripts/build-app.sh
./scripts/build-dmg.sh
./scripts/build-update.sh
```

首次 SwiftPM 解析需要联网获取 Sparkle 2.10.1 及其二进制产物。`build-app.sh` 将完整 Sparkle 框架、辅助程序和许可证装入 App，并执行嵌套签名。该框架是运行时依赖，不能按只在开发机使用的打包工具处理。

`build-dmg.sh` 需要 Python 3.10+，将现成的通用 App 打包为 `dist/TypeCount-<版本>-macOS-universal.dmg`，包含拖拽安装入口和首次使用说明，并输出 SHA-256 校验文件。Finder 排布由项目内构建工具生成；首次打包时需要联网安装 Python 依赖，仅安装到 `.build/dmg-tools`，不会放入安装包。

`build-update.sh` 使用已构建的通用 App 和本机钥匙串中的更新签名密钥，生成版本绑定的更新 ZIP、签名 feed 及相关发布资产，保存到 `dist/updates/<版本>/`。每次正式发布都必须附带本次生成的 `appcast.xml` 及其签名资产；未来的 Latest Release 如果遗漏 feed，固定检查地址会返回 404。详见 [发布流程](UPDATES.md#发布流程)。

当前 DMG 为本机开发签名测试版，未进行 Apple 公证。转发给其他 Mac 后，首次打开可能被 Gatekeeper 拦截；正式的免手动确认分发需使用 Developer ID 并完成 Apple 公证。DMG 不携带本机统计、私钥或开发配置。

最低系统版本同时写入 Swift Package 与 App 的 `Info.plist`（15.6）。默认构建本机架构，签名优先读取 `SIGN_IDENTITY`，其次读取 `.signing-identity` 中的证书 SHA-1 指纹；均未配置时会警告并回退临时签名。Apple Silicon 和 Intel 通用版本可用 `UNIVERSAL=1` 构建；向其他用户分发前仍需 Developer ID 签名和 Apple 公证。本机固定证书不代表 Apple 开发者签名或公证。本原型未进行 App Store 提审。

核心算法与存储有自动化测试；跨 App 实际输入与中文输入法准确率需要在用户授权后继续做真实场景验收。测试通过不等于已证明所有编辑器的字数准确。

实现依据：[Quartz Event Services](https://developer.apple.com/documentation/coregraphics/quartz-event-services)、[AXObserverCreate](https://developer.apple.com/documentation/applicationservices/1460133-axobservercreate)、[NSTextInputClient](https://developer.apple.com/documentation/appkit/nstextinputclient)。
